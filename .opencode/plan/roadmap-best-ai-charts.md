# RoadMap — Best-AI-Charts

Проект: «Лучшие AI модели» — статическая страница (`index.html`) со снимком данных
в `data.js`, который собирается `fetch-data.mjs` с Artificial Analysis и OpenCode.
Опубликовано: https://maxmng.github.io/Best-AI-Charts/

Порядок работ: 1–3 — гигиена и правила, 4 — живые данные на GitHub Pages,
5–6 — новый дизайн-эксперимент.

---

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Живое обновление | Только GitHub Action (без внешних сервисов и токенов) |
| Расписание сбора | Раз в сутки в 00:00 МСК = `0 21 * * *` (UTC), плюс `workflow_dispatch` |
| Стек новой страницы | Vite + React + Tailwind CSS + shadcn/ui + Framer Motion (мой выбор) |
| Скилы по дизайну | Складываем в проект (`.opencode/skills/`) |
| Публикация эксперимента | Рядом по пути: `/Best-AI-Charts/cyber/` |
| Темы | Обе: тёмная (основная, киберпанк) и светлая |
| Текущая главная | `index.html` не трогаем, остаётся как есть |

**Почему именно React-сборка, а не zero-build CDN.** Цель — показать потолок качества
UI/UX. Vite + Tailwind + shadcn/ui + Framer Motion дают самый высокий потолок: настоящие
компоненты, плавные пружинные анимации, аккуратные состояния. Чтобы это не сломало
публикацию и принцип «главная открывается двойным кликом», экспериментальная страница
собирается в **отдельную статическую папку `cyber/`** с относительными путями
(`base: './'`) и коммитится как готовые файлы. Pages при этом продолжает работать как
сейчас (сборка из ветки), а главная не затрагивается.

## UI/UX & Art Style Guidelines
- **Framework:** Always use Tailwind CSS. Never write raw CSS.

## Задача 4. Живые данные на GitHub Pages

### Что сейчас

- Кнопка «Обновить» перечитывает уже лежащий `data.js` с обходом кэша (`data.js?t=…`),
  в интернет не ходит.
- `data.js` обновляется только вручную и коммитится. На Pages это статичный файл —
  сам он никогда не меняется.

### Почему нельзя тянуть данные из браузера

Проверено:

- `artificialanalysis.ai/leaderboards/models` → 200, ~1.9 МБ HTML, **CORS нет** —
  браузер запрос заблокирует.
- Публичные CORS-прокси мертвы: `api.allorigins.win` → 522, `r.jina.ai` → 451.
- `opencode.ai/docs/go/` → 200, ~52 КБ, CORS тоже нет.

### Решение: GitHub Action (пересборка на стороне GitHub)

1. **`.github/workflows/update-data.yml`**
   - триггеры: `schedule: cron '0 21 * * *'` (00:00 МСК) и `workflow_dispatch`
     (ручной запуск кнопкой на GitHub);
   - шаги: checkout → Node 18+ → `node fetch-data.mjs` → коммит `data.js` при изменениях
     (нужны `permissions: contents: write`);
   - если сборка упала — коммита нет, старый `data.js` остаётся (скрипт уже так умеет).
   - коммит от бота, чтобы не зациклить и не перетирать ручные правки.
2. **Страница `index.html`**
   - при **открытии** — подтягивать свежий снимок с обходом кэша (fetch `data.js`
     с `cache: 'no-store'` + query-параметр), а не доверять закэшированному `<script>`;
   - по **кнопке** — то же самое (как сейчас), плюс понятный статус: «Уже актуально» /
     «Обновлено HH:MM» / «Не удалось прочитать data.js»;
   - в шапке уже есть дата снимка — она и будет показывать свежесть.
3. **Кэш CDN** Pages обходим query-параметром (`data.js?t=…`) — уже реализовано.

### Обязательная проверка в самом начале

Пробный ручной прогон воркфлоу **до** всего остального: главный риск — GitHub Actions
(дата-центр IP) не достучится до `artificialanalysis.ai`/`opencode.ai` или сайты отдадут
другую разметку. Если пробный прогон падает — вопрос обсуждаем отдельно (локальный сбор
остаётся рабочим).

## Задача 6. Эксперимент: страница `cyber/`

- **Новая** страница, `index.html` не трогаем. Публикация — `/Best-AI-Charts/cyber/`.
- **Данные и суть сохраняем полностью:** тот же `data.js` (файл берём из корня
  `../data.js`), тот же состав моделей, четыре метрики, сортировка, бейджи,
  «вне подписки», «Free», та же дата снимка. Меняются только вид, композиция и анимации.
- **Структура:**
  - `cyber-app/` — исходники (Vite, React, Tailwind, shadcn/ui, Framer Motion);
  - `cyber/` — собранная статика, коммитится (`base: './'`), её и отдаёт Pages;
  - логику метрик/форматирования переиспользуем (общий модуль или перенос).
- **Обе темы:** тёмная киберпанк (основная) + светлая, переключатель с запоминанием
  в `localStorage`, как сейчас.
- **Дизайн:** glassmorphism, неоновые glow через `box-shadow`, микро-взаимодействия
  `hover:scale-105 active:scale-95`, плавные переходы; Hi-Tech/Sci-Fi, но читаемость
  цифр и таблицы — в приоритете над эффектами.
- **Обязательное условие качества:** перед сдачей прогнать локальный предпросмотр и
  аудит по `web-design-guidelines` (доступность, клавиатура, контраст, reduced-motion).

## Что ещё нужно подтвердить перед стартом

1. **npm и внешняя сеть.** Для React-сборки нужен доступ к `registry.npmjs.org`
   (сейчас разрешены только `artificialanalysis.ai`, `opencode.ai` и локальный
   предпросмотр). Подтвердите, что можно скачивать зависимости.
2. **Сборку коммитим как файлы** (`cyber/`) — так Pages продолжает работать как сейчас,
   без смены схемы публикации. Если хотите — можно вместо этого собирать в Actions;
   но тогда изменится способ деплоя Pages. Моя рекомендация — коммитить статику.

## Риски

- GitHub Actions может не достать сайты (блок по IP / другая разметка) — проверяем
  пробным прогоном первым делом.
- Cron на GitHub задерживается и не гарантирует точность до минуты (00:00 МСК ± задержка).
- React-сборка добавляет папку с зависимостями и `node_modules/` — он уже в `.gitignore`.
- Гайдлайн Задачи 3 конфликтует с принципом «ноль зависимостей» — поэтому строго
  ограничен страницей `cyber/`.

# RoadMap — Best-AI-Charts

Проект: «Лучшие AI модели» — статическая страница (`index.html`) со снимком данных
в `data.js`, который собирается `fetch-data.mjs` с Artificial Analysis и OpenCode.

Публикация: https://maxmng.github.io/Best-AI-Charts/

## Принятые решения

| Вопрос | Решение |
| --- | --- |
| Живое обновление | Только GitHub Action (без внешних сервисов и токенов) |
| Расписание сбора | Раз в сутки в 00:00 МСК = `0 21 * * *` (UTC), плюс `workflow_dispatch` |
| Стек новой страницы | Vite + React + Tailwind CSS + shadcn/ui + Framer Motion |
| Скилы по дизайну | Складываем в проект (`.opencode/skills/`) |
| Публикация эксперимента | Рядом по пути: `/Best-AI-Charts/cyber/` |
| Темы | Обе: тёмная (основная, киберпанк) и светлая |
| Текущая главная | `index.html` не трогаем, остаётся как есть |

**Почему React-сборка.** Цель — показать потолок качества UI/UX. Vite + Tailwind +
shadcn/ui + Framer Motion дают самый высокий потолок: настоящие компоненты, пружинные
анимации, аккуратные состояния. Чтобы это не сломало публикацию, экспериментальная
страница собирается в отдельную статическую папку `cyber/` с относительными путями
(`base: './'`) и коммитится как готовые файлы. Pages продолжает работать как сейчас
(сборка из ветки), главная не затрагивается.

## 4. Живые данные на GitHub Pages

### Как было

Кнопка «Обновить» перечитывала уже лежащий `data.js` (в интернет не ходила), а сам
`data.js` обновлялся только вручную и коммитился. На Pages это статичный файл.

### Почему нельзя тянуть данные из браузера

Проверено:

- `artificialanalysis.ai/leaderboards/models` → 200, ~1.9 МБ HTML, **CORS нет** — браузер
  запрос блокирует.
- Публичные CORS-прокси мертвы: `api.allorigins.win` → 522, `r.jina.ai` → 451.
- `opencode.ai/docs/go/` → 200, ~52 КБ, CORS тоже нет.

### Сделано

1. **`.github/workflows/update-data.yml`** — сборка на стороне GitHub:
   - триггеры `schedule: cron '0 21 * * *'` (00:00 МСК) и `workflow_dispatch`;
   - шаги: checkout → Node 20 → `node fetch-data.mjs` → коммит `data.js`, если он изменился;
   - при падении сборки коммита нет — старый снимок остаётся (скрипт уже так умеет).
2. **`index.html`** — при открытии страница тихо подтягивает свежий `data.js` с обходом
   кэша; кнопка «Обновить» делает то же явно, с сообщением статуса. Если снимок не
   изменился, перерисовки нет (не мигает и не гоняет анимацию заново); выбранная метрика
   при обновлении сохраняется.

### Обязательная проверка (осталась)

Ручной прогон воркфлоу: убедиться, что раннеры GitHub достают AA и OpenCode. Если
прогон падает — обсуждаем отдельно, локальный сбор остаётся рабочим.

## 6. Эксперимент: страница `cyber/` (не начата)

- **Новая** страница, `index.html` не трогаем. Публикация — `/Best-AI-Charts/cyber/`.
- **Данные и суть сохраняем полностью:** тот же `data.js` (берём `../data.js`), тот же
  состав моделей, четыре метрики, сортировка, бейджи, «вне подписки», «Free», дата снимка.
  Меняются только вид, композиция и анимации.
- **Структура:** `cyber-app/` — исходники (Vite, React, Tailwind, shadcn/ui, Framer Motion);
  `cyber/` — собранная статика, коммитится, её отдаёт Pages.
- **Обе темы** с переключателем и `localStorage`.
- **Дизайн:** glassmorphism, неоновые glow через `box-shadow`, микро-взаимодействия
  `hover:scale-105 active:scale-95`; Hi-Tech/Sci-Fi, но читаемость цифр и таблицы важнее
  эффектов.
- **Перед сдачей:** локальный предпросмотр + аудит по `web-design-guidelines`
  (доступность, контраст, клавиатура, reduced-motion).

## Риски

- GitHub Actions может не достать сайты (блок по IP / другая разметка) — проверяем
  ручным прогоном первым делом.
- Cron на GitHub задерживается и не гарантирует точность до минуты.
- React-сборка добавляет `node_modules/` — он уже в `.gitignore`.
- Гайдлайн Задачи 3 конфликтует с принципом «ноль зависимостей» — поэтому строго
  ограничен страницей `cyber/`.
